## 1. 设计哲学与理论基础

### 1.1 核心问题：从论文到演示的信息损失是不可避免的

一篇典型学术论文在完整展示时需要 30–60 张幻灯片，但学术演示通常只有 15–25 分钟（对应 15–25 张）。因此压缩率约为 50%–70%，且不能随机删除——删错了叙事就断了。

**理论依据：信息价值的非均匀分布（Power-law of Information Importance）**  
学术内容并非等价的：一篇方法论文中，方法细节和实验结果承载了 80% 的核心贡献，而背景介绍、相关工作等属于"脚手架内容"，在已建立领域认知的审稿人/听众面前可以大幅压缩。这对应 `ROLE_BASE` 中 `method_component=1.45` vs `hook_context=0.65` 的设计选择。

### 1.2 约束驱动（Constraint-Driven）vs 优化驱动（Optimization-Driven）

本方案**不是**"最优化某个叙事得分函数"，而是：

> **先满足所有硬约束（叙事骨架 + 视觉完整），再在剩余自由度内最大化信息密度。**

这源于面向演示质量的两个不可妥协的需求：

- **叙事完整性（Narrative Completeness）**：听众必须能跟上逻辑链，即使压缩后，开头/问题/方法/结论四段必须在场。
- **证据可信度（Evidence Credibility）**：图表公式是学术演示的"证明材料"，删除等同于去掉证据链，会严重损害说服力。

因此，本算法的优先级序严格遵循：  
`视觉安全 > 叙事下限 > 锚点完整 > 信息密度最大化`

### 1.3 为什么不用 LLM 直接做压缩？

LLM 做压缩存在三个工程问题：
1. **重现性差**：同一输入可能每次输出不同的页集合，难以调试。
2. **无法保证视觉引用完整性**：LLM 没有结构感知，可能删掉含图的页。
3. **成本高**：37 张幻灯片的内容发给 LLM 评估需要大量 token。

本算法用规则系统处理结构约束，LLM 只负责它最擅长的"语义角色标注"（在上游用），两者分工明确。

## 2. 全局参数层（静态配置）

### 2.1 角色权重表 `ROLE_BASE`

| 角色 | 权重 | 设计意图 |
|---|---|---|
| `theoretical` | **1.60** | 推导/证明最难替代，删掉会让论点失去数学依据 |
| `method_component` | **1.45** | 技术细节是核心贡献所在 |
| `method_overview` / `results` | **1.20** | 提供结构骨架和实证结论 |
| `analysis_ablation` | **1.10** | 消融分析是证明设计选择的关键 |
| `problem_definition` | **1.00** | 基准（锚点），问题不清则一切无意义 |
| `gap_limitations` / `experiment_setup` / `overview_figure` | 0.95/0.90 | 支持性、上下文性内容 |
| `insight_thesis` | **0.85** | 核心论点但通常简短，信息密度有限 |
| `related_work` / `takeaways` | **0.75** | 背景/总结类，相对可压缩 |
| `hook_context` | **0.65** | 铺垫，在领域熟悉的听众面前可高度压缩 |
| `limitation_future` | **0.60** | 演示中常省略，时间不足时首选删除 |

**理论依据：信息冗余理论（Shannon Redundancy）**  
权重反映内容在演示中的"不可替代性"。高权重角色一旦删除，其携带的信息无法被其他页补偿（例如实验结果）；低权重角色携带的信息往往可以推断或省略（例如背景动机听众通常已知）。

### 2.2 叙事分组模板 `NARRATIVE_GROUPS`

7 个组，每组定义：
```
(group_name, [roles], static_frac, min_slides, max_slides)
```

- `static_frac`：当前版本保留为注释/文档用，实际分配已替换为动态载荷比。
- `min`/`max`：组级的硬性滑动窗口约束。

**理论依据：演示叙事结构理论（Presentation Narrative Arc）**  
借鉴 Minto Pyramid Principle 和学术演讲的 IMRAD 结构变体：问题先行、方法支撑、证据结尾。7 个组本质上是 IMRAD（Introduction/Method/Results/Discussion）的细分映射。

### 2.3 硬下限 `GROUP_FLOOR`

```python
GROUP_FLOOR = {
    "opening":  1,   # 必须有开场
    "problem":  1,   # 必须定义问题
    "related":  1,   # 至少一张先行工作
    "thesis":   1,   # 我们的方案必须出现
    "method":   3,   # 最少：概述 + 1个组件 + 理论
    "evidence": 3,   # 最少：数据集 + 主结果 + 1个分析
    "closing":  1,   # 必须有收尾
}
```

**理论依据：叙事完整性的最小充分条件**  
这是"演示能被听众理解"的最低信息集合——去掉任何一个则叙事出现断层。例如 method=3 确保听众能看到"模型总体是什么"+"至少一个技术细节"+"为什么这样设计"。

### 2.4 锚点角色 `GROUP_PRIORITY_ROLE`

每组一个"必须尽量在场"的角色：
```python
GROUP_PRIORITY_ROLE = {
    "opening":  "hook_context",
    "problem":  "problem_definition",
    "related":  "related_work",
    "thesis":   "insight_thesis",   # 论文核心思想 > 架构图
    "method":   "method_overview",  # 先有全局再有细节
    "evidence": "results",          # 结果是证据的核心
    "closing":  "takeaways",
}
```

**理论依据：认知加载理论（Cognitive Load Theory）**  
听众在没有先行框架（overview）的情况下处理细节会产生极高的认知负担。锚点角色为每个叙事阶段提供"框架先行"的认知脚手架，压缩时优先保留。

## 3. Pass 1 — 语义入模与分组路由

### 3.1 角色与载荷赋值

```python
s["_role"] = s.get("role", "method_component")  # 直接读 LLM 预标注
s["_load"] = ROLE_BASE.get(s["_role"], 1.0)     # 查权重表
```

- 回退策略：LLM 未标注时默认 `method_component`（高权重保守策略，宁可高估一张无名页的重要性）。
- `_load` 同时服务于：预算分配（Pass 2-A）和保留评分（keep_score）。

### 3.2 分组路由与孤儿页兜底

```python
# 未命中 role_to_group 的页 → 回退到 method
for s in ungrouped:
    groups["method"].append(s)
```

**设计意图**：LLM 有时会返回未见过的角色名（如 `contribution_list`），兜底到 method 而非丢弃，是必要的鲁棒性措施。

## 4. Pass 2-A — 预算分配（算账层）

### 4.1 组载荷计算

$$\text{group\_load}[g] = \sum_{s \in \text{group}[g]} \text{ROLE\_BASE}[s.\text{role}]$$

**计算依据**：不用滑动页数，而是用"叙事分量"驱动预算，这样内容密集的组（method 有 12 张重角色页）自然拿到更多压缩后的页配额。

### 4.2 动态载荷比

$$\text{frac\_dynamic}[g] = \frac{\text{group\_load}[g]}{\sum_g \text{group\_load}[g]}$$

在当前示例数据（37 张）中，method(41.4%) + evidence(34.7%) 合计 76.1%，因此它们合计拿到接近 4/5 的额外预算——这符合学术演示以方法和结果为核心的预期。

### 4.3 强制地板 `mandatory_floor`

$$\text{mandatory\_floor} = \sum_{g \neq \emptyset} \min(\text{GROUP\_FLOOR}[g], |\text{group}[g]|)$$

空组不计入地板，防止某组因无候选页而虚增地板造成预算浪费。

### 4.4 目标自动修正

$$\text{effective\_target} = \max(\text{target\_n},\ \text{mandatory\_floor})$$

```python
extra_budget = effective_target - mandatory_floor
```

**理论依据：最小破坏原则（Minimum Disruption Principle）**  
用户指定的 `target_n` 是期望，但叙事完整性是硬约束。当两者冲突时，优先保叙事，以最小的页数增量满足硬约束，而非强行删到目标造成叙事断层。

### 4.5 每组最终预算

$$\text{extra\_for\_group}[g] = \text{round}(\text{extra\_budget} \times \text{frac\_dynamic}[g])$$

$$\text{budget}[g] = \max\!\bigl(\text{floor}[g],\ \min(\text{floor}[g] + \text{extra}[g],\ \text{max}[g],\ |\text{raw}[g]|)\bigr)$$

三重截断顺序：下限优先 → 取组上界与实际页数的较小值。

## 5. Pass 2-B — 组内压缩（`compress_group`）

每组独立执行，顺序为：**视觉保护 → 去重 → 合并 → 删除**。

### 5.1 视觉钉扎（Visual Pinning）

```python
def _has_visuals(slide):
    vr = slide.get("visual_refs", {})
    return bool(vr.get("images") or vr.get("tables") or vr.get("equations"))

pinned       = [s for s in slides if _has_visuals(s)]
compressible = [s for s in slides if not _has_visuals(s)]
```

- 有图/表/公式的页 → `pinned`，直接传到输出，不参与任何压缩操作。
- 若 `len(pinned) >= budget`：返回全部 pinned 页，该组预算自动抬升。

**理论依据：证据锚定效应（Evidence Anchoring）**  
实验心理学研究表明，视觉图表显著提升听众对论点的信任度和记忆保留率（Mayer, 2009，多媒体学习理论）。学术演示中，一张实验结果表或架构图的说服力远超同等信息的文字表述。因此视觉元素必须被视为"不可压缩单元"，而非普通幻灯片。

### 5.2 文本页去重

```python
for s in sorted(compressible, key=keep_score, reverse=True):
    if title not in seen_titles:
        deduped.append(s)
```

按质量降序遍历，遇到重复标题只保留得分最高版本。`seen_titles` 初始包含 pinned 页标题，防止文本页与视觉页同名共存。

### 5.3 合并判定 `_should_merge`

**前提条件（必须）**：`s1["section_name"] == s2["section_name"]`（只在同章节内合并）

**触发条件（满足其一）**：

| 条件 | 公式 | 含义 |
|---|---|---|
| 高内容重叠 | $J(A,B) = \frac{\|A \cap B\|}{\|A \cup B\|} > 0.25$ | 两页有 >25% 相同 bullet |
| 双短页 | $\|A\| \leq 3 \text{ and } \|B\| \leq 3$ | 两页都是浅内容，合并无信息损失 |

**理论依据：信息论视角（Information-Theoretic Merge Criterion）**  
Jaccard 相似度 > 0.25 意味着合并后的信息增量（union - intersection）相对于两页总信息量不超过 75%，即合并代价可控。"双短页"规则则是"信息密度太低，不如合并"的直接启发式。

### 5.4 合并执行 `merge_slides`

```python
merged = copy.deepcopy(s1)          # primary = keep_score 高的页
for pt in s2["content_points"]:     # 追加 secondary 独有 bullet
    if pt not in existing:
        merged["content_points"].append(pt)
merged["content_points"] = merged["content_points"][:5]   # 截断到 5 条
# 若 primary 无视觉，继承 secondary 的视觉引用
merged["_merged_from"] = [...] + [s2["slide_title"]]      # 审计链
```

**设计意图**：
- 以高质量页为主干，吸收增量信息，避免信息从高质量页流向低质量页。
- 5-bullet 上限防止合并后单页信息过载（演示幻灯片的认知负载研究表明，5±2 条目是工作记忆上限——Miller's Law）。

### 5.5 合并循环机制

```python
changed = True
while changed and len(compressible) > text_budget:
    changed = False
    for i, j in all_pairs:
        if _should_merge(i, j):
            # 合并 → 重置 changed=True → 从头遍历
            break
```

**计算依据**：贪心式单步合并（每次只做一次合并就重置），确保每次合并后重新评估配对关系。这避免了连续多次合并导致的错误传播，但在极端情况下是 $O(n^3)$ 的复杂度——对幻灯片规模（< 50 张）完全可接受。

### 5.6 删除阶段（最后手段）

```python
compressible = sorted(compressible, key=keep_score, reverse=True)[:text_budget]
```

若合并后仍超预算，纯粹按分数截断。这是"无法通过语义整合压缩时的最终裁剪"。

## 6. `keep_score` 的数学结构

$$\boxed{\text{score} = \text{load} \times (1 + 0.3 \times C + 0.2 \times V)}$$

**各项定义**：

$$C = \frac{\min(|\text{content\_points}|,\ 5)}{5} \in [0, 1] \quad \text{（内容密度）}$$

$$V = \min\bigl(0.5 \times |\text{images}| + 0.8 \times |\text{tables}| + 0.3 \times |\text{equations}|,\ 1.0\bigr) \in [0, 1] \quad \text{（视觉丰富度）}$$

**分数范围分析**：

| 情景 | load | C | V | score |
|---|---|---|---|---|
| theoretical 满内容满表格 | 1.60 | 1.0 | 1.0 | **2.40** |
| method_component 满内容无视觉 | 1.45 | 1.0 | 0 | **1.885** |
| hook_context 满内容满图 | 0.65 | 1.0 | 1.0 | **0.975** |
| limitation_future 空内容空视觉 | 0.60 | 0 | 0 | **0.60** |

**理论依据：乘法加成结构的设计意图**  
加成因子 $(1 + 0.3C + 0.2V)$ 的范围是 $[1.0, 1.5]$，即最多将基础分提升 50%。这保证了：

1. **角色优先**：即使 hook_context 拥有最丰富的视觉和内容，其最高分（0.975）仍低于任何纯文本 method_component（1.45）——叙事角色决定了上界。
2. **质量打破同角色平局**：同为 method_component 的两张页，有 3 个图的会优先于空页保留。
3. **表格>图>公式**（0.8 > 0.5 > 0.3）：反映了在学术演示中，数据型表格（直接对比数字）比示意图（需要解读）更具证明力，公式独立出现时信息密度相对较低。

## 7. Pass 2-C — 锚点角色补位（Priority Guarantee）

### 7.1 触发条件

每组压缩完成后，检查该组锚点角色是否在结果中存在：

```python
has_priority = any(s["_role"] == priority_role for s in result)
```

若不存在，进入补位流程。

### 7.2 补位执行

```python
best_priority = max(candidates, key=keep_score)            # 最优锚点候选
swappable = [s for s in result
             if s["_role"] != priority_role
             and not _has_visuals(s)]                      # 可替换池：非锚点 & 非视觉
```

- 若 `swappable` 非空：替换其中得分最低者（页数不变）。
- 若 `swappable` 为空（全被视觉页占据）：直接 append，该组 +1 页。

**理论依据：双层约束的协同保护**  
视觉钉扎和锚点补位可能同时激活（当 pinned 页数已满组预算时，锚点页只能 append）。这个"允许超额"的设计选择体现了：**演示质量约束 > 页数约束**。多 1 张页的代价，远小于缺少核心结果或方法概述的叙事损失。

## 8. Pass 3 — 叙事重排

### 8.1 组顺序（宏观，跨组）

```
论文顺序（IMRAD）: Introduction → Related Work → Method → Experiment → Conclusion
演示顺序（说服弧）: opening → problem → related → thesis → method → evidence → closing
```

**关键差异与理论依据**：

| 位置变化 | 论文顺序 | 演示顺序 | 原因 |
|---|---|---|---|
| related work 前移 | 第 2 节，方法前 | thesis 之前，problem 之后 | 演示中先建立"别人的问题"，再引出"我们的答案"，逻辑更紧凑 |
| gap/limitations 整合 | 分散在 intro | 紧跟 problem_definition | 问题→缺陷→方案 形成完整的"动机链" |
| experiment_setup 前置 | 实验节开头 | evidence 组首位 | 先建立实验可信度，再展示数字，避免听众对数字来源产生疑虑 |

**理论依据：Monroe Motivated Sequence（门罗动机序列）**  
这是说服性演讲的经典五步结构：Attention（hook）→ Need（problem）→ Satisfaction（thesis + method）→ Visualization（evidence）→ Action（closing）。本算法的7组结构是该序列在学术演示场景下的直接映射。

### 8.2 Section 顺序索引（组内，微观）

```python
_section_order: dict[str, int] = {}
for s in slides:
    sec = s.get("section_name", "")
    if sec not in _section_order:
        _section_order[sec] = len(_section_order)  # 首次出现顺序
```

**目的**：同角色多页按原论文章节推进顺序排列（如 §4.1 → §4.2 → §4.3），而非仅靠得分打序，避免听众在 method 段看到乱序的技术组件。

### 8.3 组内三键排序 `intra_order`

```python
return (ri, sec_i, -keep_score(slide))
```

| 键 | 类型 | 决定什么 |
|---|---|---|
| `ri = _ROLE_ORDER.index(role)` | int（越小越靠前） | 组内角色叙事语法顺序 |
| `sec_i = _section_order[section_name]` | int（越小越靠前） | 同角色内的章节推进顺序 |
| `-keep_score(slide)` | float（越小越靠前，降序） | 同角色同章节下优先高质量页 |

**实际效果（method 组示例）**：

```
06 [method_overview   ] HiAGM Model Overview           ← ri=6，先于 method_component(ri=7)
07 [method_component  ] Bayesian (§4.1)                ← sec_i=最小
08 [method_component  ] BiTree-LSTM (§4.2)             ← sec_i 次之
09 [method_component  ] GCN (§4.2)                     ← 同 section，按 keep_score 降序
10 [method_component  ] HiAGM-LA (§4.3)
11 [method_component  ] HiAGM-TP (§4.3)
12 [theoretical       ] Hierarchy Encoding Equations   ← ri=8，放在 component 之后
```

**理论依据：渐进式披露（Progressive Disclosure）**  
认知科学研究表明，先呈现高层框架再逐步深入细节，比先列细节后汇总，能显著降低认知负担（Sweller, 1988，认知负载理论）。`method_overview`（ri 最小）先于 `method_component` 正是这一原则的直接实现。

## 9. 输出与可审计性

### 9.1 内部字段清洗

```python
cs = {k: v for k, v in s.items() if not k.startswith("_")}
```

### 9.2 决策报告 `print_report`

对每张原始输入幻灯片，标注三种决策之一：

- `MERGE → 目标页`：被合并吸收，具体合并目标可追溯

## 10. 约束优先级总结

```
优先级（从高到低）：

① 视觉证据不丢       ← 硬约束，由 pinned + swappable 排除双重保护
② 叙事骨架不断        ← 硬约束，由 GROUP_FLOOR + effective_target 保证
③ 组锚点尽量在场      ← 软硬混合，尽力 swap，不可时允许 +1 页
④ 信息密度最大化      ← 软优化目标，由 keep_score 驱动的 merge/delete
```

**对"输出页数超过 target_n"的解释**：

这是上述多层约束叠加的正当结果，不是 bug：
- 视觉钉扎使 method/evidence 组自动扩容
- 锚点补位在无可替换槽时 +1 页
- `mandatory_floor` 在 target_n 过低时强制抬升

算法设计选择是：**宁可超额 1–4 页，不破叙事与证据完整性。** 这符合"演示质量优先"的基本目标。
