# 第四章 基于结构化中间表示的演示文稿生成方法

## 4.1 引言

从学术论文自动生成演示文稿的核心挑战在于：论文所遵循的写作逻辑（IMRAD 结构——引言、方法、实验、结论的线性展开）与演示文稿所要求的叙事逻辑（从问题引出解法、以证据支撑结论的说服性弧线）在本质上存在显著差异。论文写作以信息完备性为首要目标，其结构服务于同行评审的全面验证；演示则以说服效果为首要目标，其结构服务于有限时间内的听众认知。两者之间的张力，使得简单的文本截取或关键词提取方法无法胜任。

本章提出了一套**基于结构化中间表示**的演示文稿生成方法（图 4-1）。该方法的核心思想是：在论文内容与最终演示文稿之间引入一个明确的**幻灯片素材池**（Slide Pool）作为中间表示层，借助大语言模型将论文内容规划为候选幻灯片的集合，再由一套基于约束驱动的叙事重排算法（Narrative Reorder）将候选池压缩并重组为叙事连贯、视觉完整、页数受控的演示文稿大纲。

与端到端生成范式（directly prompting LLM for slides）或基于段落摘要的方法相比，本方法具有以下优势：

- **可审计性**：素材池是人类可读的结构化 JSON，每张候选幻灯片携带明确的叙事角色（role）、内容要点（content_points）和视觉引用（visual_refs），中间结果完全透明。
- **叙事可控性**：叙事重排算法由静态规则驱动，输出完全可重现，可在不重新调用大语言模型的情况下通过参数调整改变压缩策略。
- **视觉一致性**：视觉元素在素材池阶段完成 ID 级对齐，从源头消除了幻觉引用；叙事重排阶段对含视觉幻灯片实施不可删除的钉扎保护，确保图表完整性贯穿全流程。

本章的组织结构如下：第 4.2 节介绍幻灯片素材池的设计与构建；第 4.3 节阐述叙事角色分类体系；第 4.4 节详细分析三阶段叙事重排算法；第 4.5 节说明系统整体流程与输出格式；第 4.6 节为本章小结。

## 4.2 幻灯片素材池：结构化中间表示的设计

幻灯片素材池（Slide Pool）是贯穿本方法的核心数据结构。其设计目标是将论文的信息内容从自由文本的连续形式转换为结构化的离散单元，每个单元对应一张候选幻灯片（Candidate Slide），并携带足够的语义元数据支撑后续的压缩与重排决策。

### 4.2.1 候选幻灯片的内容单元格式

每张候选幻灯片以如下 JSON 数据结构表示：

```json
{
  "slide_id":      6,
  "slide_title":   "HiAGM: Two-Stream Information Propagation",
  "section_name":  "3 Methodology",
  "role":          "method_overview",
  "slide_purpose": "Introduce the overall dual-stream architecture of HiAGM.",
  "content_points": [
    "HiAGM adopts a two-stream design: local matching and global propagation.",
    "Text encoder and structure encoder work in parallel.",
    "Output representations are fused for hierarchical classification."
  ],
  "visual_refs": {
    "images": [
      {
        "type":          "image",
        "id":            2,
        "img_path":      "images/hiagm_arch.jpg",
        "caption":       "Figure 2: The HiAGM architecture.",
        "analysis_text": "该图展示了双流信息传播架构，左侧为文本编码器，右侧为层次结构编码器..."
      }
    ],
    "tables":    [],
    "equations": []
  }
}
```

各字段的语义与设计意图如表 4-1 所示。

**表 4-1　候选幻灯片字段设计**

| 字段 | 类型 | 语义说明 |
|---|---|---|
| `slide_id` | int | 全局递增唯一编号，按章节 IMRAD 顺序赋值 |
| `slide_title` | str | 幻灯片标题，由大语言模型生成 |
| `section_name` | str | 所属论文章节（`section_name` 来自解析树） |
| `role` | str | 叙事角色标签，从 14 种预定义角色中选一 |
| `slide_purpose` | str | 本页叙事目的的单句描述，支撑重排决策 |
| `content_points` | list[str] | 幻灯片主要内容要点，不超过 5 条 |
| `visual_refs` | object | 已验证存在的图/表/公式引用，携带路径与语义描述 |

`section_name` 字段在叙事重排阶段具有双重作用：一方面作为组内排序的第二键（按原论文章节推进顺序排列同角色幻灯片），另一方面作为合并约束（`merge_slides` 仅在同章节内执行），保证了压缩操作的语义合理性。

### 4.2.2 素材池的生成流程

素材池的生成依托于第三章所描述的解析-理解管道，其完整流程见图 4-1。在调用大纲规划大语言模型（`analyze_outline` 工作流接口）时，系统按论文 IMRAD 章节顺序逐章传入如下结构化输入：

```json
{
  "abstract":     "...(论文摘要，全局上下文)...",
  "section_name": "3 Methodology",
  "content":      "...(章节完整正文)...",
  "refs": {
    "images":    [{ "id": 2, "analyze_text": "该图展示了双流架构..." }],
    "equations": [{ "id": 3, "analyze_text": "该公式定义了层次传播损失..." }],
    "tables":    [{ "id": 1, "analyze_text": "该表对比了数据集分布..." }]
  }
}
```

`refs.analyze_text` 来自多模态语义分析的结果，是视觉元素与文本规划之间的语义桥梁。模型基于章节正文与视觉语义描述，为本章节生成若干候选幻灯片，每张幻灯片独立携带 `role`、`slide_purpose`、`content_points` 和对 `refs` 中元素 ID 的引用。

系统提示词（System Prompt）对模型施加四层硬约束：（1）任务定义层——输出纯 JSON，第一个字符为 `{`，最后一个字符为 `}`；（2）角色约束层——`role` 必须恰好从 14 种预定义角色中选取一种，不得发明新角色；（3）规划原则层——内容须忠实于输入文本，不得引入输入中不存在的信息；（4）视觉引用约束层——`visual_refs` 中的 ID 必须且仅能来自输入 `refs` 字段提供的 ID，禁止生成或改写 ID。层（4）从算法层面消除了模型引用不存在图表的可能性。

所有章节的候选幻灯片拼接后形成完整的素材池。一篇典型的 NLP 会议论文（12 个章节）可产生约 30–40 张候选幻灯片，保留论文 IMRAD 章节顺序，每张幻灯片均携带 `role` 标签。素材池随后作为叙事重排模块的输入。

## 4.3 叙事角色分类体系

叙事角色（Presentation Role）是贯穿本方法的核心语义接口：在素材池阶段，由大语言模型的约束型提示词赋予每张候选幻灯片一个角色标签；在叙事重排阶段，由规则系统读取角色标签进行分组路由、预算分配和优先级排序。两个模块之间形成明确的**数据合约**（Contract），使系统在保持模块独立可测的同时实现端到端的语义一致性。

### 4.3.1 14 种叙事角色的定义

系统将学术演示中可能出现的幻灯片功能归纳为 14 种叙事角色，定义如表 4-2 所示。

**表 4-2　叙事角色分类体系（14-Role Taxonomy）**

| 角色标识 | 叙事功能 | 典型内容 | 叙事分量权重 |
|---|---|---|---|
| `hook_context` | 研究背景与动机引入 | 应用场景、现实需求、研究意义 | 0.65 |
| `related_work` | 相关工作综述 | 先行方法、技术演进、文献对比 | 0.75 |
| `problem_definition` | 问题形式化定义 | 任务描述、输入输出定义、符号系统 | 1.00 |
| `gap_limitations` | 现有方法局限性 | 已有工作的不足、本文动机 | 0.95 |
| `insight_thesis` | 核心洞见与贡献陈述 | 关键思想、主要贡献列表 | 0.85 |
| `overview_figure` | 整体架构图说明 | 模型总体设计图、流程图 | 0.95 |
| `method_overview` | 方法宏观架构介绍 | 多模块协同关系、整体设计思路 | 1.20 |
| `method_component` | 具体模块深度解析 | 单一技术组件的输入输出与计算过程 | 1.45 |
| `theoretical` | 理论推导与复杂度分析 | 数学证明、公式推导、收敛性分析 | 1.60 |
| `experiment_setup` | 实验配置说明 | 数据集、基线方法、评估指标、训练设置 | 0.90 |
| `results` | 主实验结果 | 对比实验表格、性能数字 | 1.20 |
| `analysis_ablation` | 消融与深度分析 | 消融实验、参数敏感分析、误差分析 | 1.10 |
| `takeaways` | 结论与贡献总结 | 主要发现、研究意义 | 0.75 |
| `limitation_future` | 局限性与未来工作 | 当前不足、研究展望 | 0.60 |

### 4.3.2 叙事分量权重的设计依据

表 4-2 第四列列出了各角色的**叙事分量权重**（Narrative Load Weight），该权重直接对应叙事重排算法中的 `ROLE_BASE` 字典，量化了每种叙事功能的"不可替代性"。权重的设计依据如下：

**高权重角色（≥ 1.10）** 对应内容一旦删除便无法从其他页补偿的核心内容：`theoretical`（1.60）包含数学推导，是方法正确性的直接证明；`method_component`（1.45）描述技术细节，是贡献的核心载体；`results`（1.20）和 `method_overview`（1.20）分别提供实证支撑和整体框架。

**中权重角色（0.85–1.00）** 对应支撑性或过渡性内容：`problem_definition`（1.00）是叙事逻辑的起点，缺失会导致后续铺垫失去根基；`gap_limitations`（0.95）和 `overview_figure`（0.95）是动机建立和整体呈现的关键过渡。

**低权重角色（≤ 0.75）** 对应在领域熟悉的听众面前可高度压缩的内容：`hook_context`（0.65）和 `limitation_future`（0.60）承载的铺垫信息和展望内容，在有限演示时间内往往优先压缩。

这一权重设计遵循信息冗余理论的基本原理：高权重角色的信息在其他页面中无互补，低权重角色的信息对已掌握领域背景的听众而言可推断或省略。

### 4.3.3 角色与叙事分组的映射

14 种角色被进一步归并为 7 个**叙事叙事组**（Narrative Group），形成宏观叙事结构层级。每个分组拥有：角色集合、叙事地板（`GROUP_FLOOR`，该组至少需要保留的幻灯片数量）和锚点角色（`GROUP_PRIORITY_ROLE`，该组最优先保留的角色）。7 个叙事组的定义见表 4-3。

**表 4-3　叙事分组设计**

| 组名 | 包含角色 | 叙事地板 | 锚点角色 | 叙事功能 |
|---|---|---|---|---|
| `opening` | `hook_context` | 1 | `hook_context` | 吸引注意，建立问题情境 |
| `problem` | `problem_definition`、`gap_limitations` | 1 | `problem_definition` | 形式化问题，揭示已有不足 |
| `related` | `related_work` | 1 | `related_work` | 建立技术背景，区分本文贡献 |
| `thesis` | `insight_thesis`、`overview_figure` | 1 | `insight_thesis` | 提出核心思想，给出全局视角 |
| `method` | `method_overview`、`method_component`、`theoretical` | 3 | `method_overview` | 展开技术细节，建立方法可信度 |
| `evidence` | `experiment_setup`、`results`、`analysis_ablation` | 3 | `results` | 提供实证证据，支撑方法有效性 |
| `closing` | `takeaways`、`limitation_future` | 1 | `takeaways` | 总结贡献，指向研究展望 |

叙事地板约束确保了叙事骨架的最小必要完整性——即在任何压缩力度下，上述 7 个叙事阶段至少各有一页幻灯片在场，使听众能跟上完整的论证逻辑链。

## 4.4 三阶段叙事重排算法

叙事重排（Narrative Reconstruction）算法以带角色标注的候选幻灯片池为输入，以用户指定的目标页数 $N_{target}$ 为约束，输出页数受控、叙事连贯的最终演示文稿大纲。算法分为三个阶段执行（图 4-2）：**Pass 1** 完成语义入模与分组路由；**Pass 2** 在各叙事组内独立执行预算分配与内容压缩；**Pass 3** 执行跨组叙事重排，将 IMRAD 章节顺序重组为演示说服弧。

### 4.4.1 设计哲学：约束驱动而非优化驱动

算法的核心范式是**约束驱动（Constraint-Driven）**而非优化驱动——算法并不寻求某个叙事得分函数的最优解，而是：

> **先满足所有硬约束（叙事骨架不断 + 视觉元素不丢），再在剩余自由度内最大化信息密度。**

这一选择源于学术演示质量的两个不可妥协的需求：叙事完整性（听众必须能跟上论证逻辑链）与证据可信度（实验图表是学术说服力的核心载体）。硬约束的优先级序为：

$$\text{视觉证据保全} > \text{叙事骨架完整} > \text{锚点角色在场} > \text{信息密度最大化}$$

此设计有别于直接用大语言模型做压缩的方案：大语言模型的压缩输出难以保证重现性与视觉引用完整性，且大规模候选池的 token 成本高。本算法用规则系统处理结构约束，大语言模型只负责上游的语义角色标注，两者分工明确。

### 4.4.2 Pass 1：语义入模与分组路由

**角色赋值**：读取每张候选幻灯片的 `role` 字段，在 `ROLE_BASE` 权重字典中查找对应的叙事分量载荷（`_load`）。对于 `role` 字段缺失或未知的边界情况，回退至 `method_component`（1.45）——高权重的保守策略确保未知页不被轻易删除。

**分组路由**：依据角色-分组映射将每张候选幻灯片分发至对应的叙事组。未命中任何预设映射的角色（如大语言模型偶发的角色名变体）一律归入 `method` 组，防止幻灯片因分类失败而丢失。

### 4.4.3 Pass 2-A：基于叙事载荷的预算分配

**分组载荷计算**：每个叙事组的分组载荷（Group Narrative Load）定义为该组所有候选幻灯片的叙事分量权重之和：

$$L_g = \sum_{s \in \text{group}_g} \text{ROLE\_BASE}[s.\text{role}]$$

各组的**动态载荷比** $f_g$ 由各组载荷相对于全局总载荷的比例决定：

$$f_g = \frac{L_g}{\sum_{g'} L_{g'}}$$

动态载荷比驱动预算分配而非固定分数，使内容密集的组（如 method 组具有大量高权重候选幻灯片）能自然获得更多压缩后的页配额，符合学术演示以方法和结果为核心的预期。

**强制地板**：叙事骨架的最小必要规模由强制地板（mandatory floor）保证：

$$F = \sum_{g \neq \emptyset} \min(\text{GROUP\_FLOOR}[g],\ |\text{group}_g|)$$

仅对候选幻灯片非空的组计入地板，防止空组虚增地板导致预算浪费。

**有效目标自动修正**：

$$N_{\text{eff}} = \max(N_{\text{target}},\ F)$$

$$\text{额外预算} = N_{\text{eff}} - F$$

当用户指定目标低于叙事最小规模时，有效目标自动抬升以保护叙事完整性，以最小页数增量满足硬约束，而非强行压缩造成叙事断层。

**每组最终预算**：

$$\text{budget}_g = \max\!\bigl(\text{floor}_g,\ \min(\text{floor}_g + \lfloor\text{额外预算} \times f_g\rfloor,\ \text{max}_g,\ |\text{group}_g|)\bigr)$$

三重截断依次应用：下限优先（不低于地板）→ 上限截断（不超过组上界与实际候选数之较小值）。

### 4.4.4 Pass 2-B：组内压缩

在每个叙事组内，以组预算为目标，按照**视觉保护 → 文本去重 → 语义合并 → 得分删除**的顺序执行压缩，分四步进行。

**步骤一：视觉钉扎（Visual Pinning）**

含有图片、表格或数学公式引用的幻灯片被标记为视觉钉扎页（`pinned`），不参与任何删除或合并操作：

$$\text{pinned} = \{s \in \text{group}_g \mid |\text{visual\_refs}(s)| > 0\}$$

若 $|\text{pinned}| \geq \text{budget}_g$，组预算自动上调至 $|\text{pinned}|$，确保视觉元素不因预算不足而被删除。

此设计的理论依据来自多媒体学习理论（Mayer，2009）：视觉图表显著提升听众对论点的信任度与记忆保留率。学术演示中，一张实验结果表或架构图的说服力远超同等信息量的纯文字描述，因此视觉元素须被视为"不可压缩单元"。

**步骤二：文本页去重（Deduplication）**

对非钉扎页（`compressible`），按保留得分（`keep_score`，见第 4.4.5 节）降序遍历，遇到重复标题只保留得分最高版本。`seen_titles` 集合初始包含所有钉扎页的标题，防止出现同标题的文本页与视觉页共存的冗余情况。

**步骤三：语义合并（Semantic Merge）**

当文本页数量仍超出文本预算（$\text{budget}_g - |\text{pinned}|$）时，对可压缩页两两检测合并条件：

- **合并前提**：两页属于同一论文章节（`section_name` 相同），确保合并操作不跨越语义边界。
- **合并触发（满足其一）**：
  - **高内容重叠**：两页 `content_points` 集合的 Jaccard 系数 $J(A,B) = |A \cap B| / |A \cup B| > 0.25$；
  - **双短页**：两页 `content_points` 均不超过 3 条。

合并执行时，以保留得分高者为主干（primary），将次页（secondary）中不重复的 `content_points` 追加至主干，并截断至不超过 5 条（符合 Miller 定律的工作记忆上限 $7 \pm 2$）。若主干页无视觉引用而次页有，则继承次页的视觉引用，防止视觉元素随文本页被合并消失。每次合并操作均记录审计链（`_merged_from`），支持压缩决策的事后溯源。

合并以贪心式单步方式循环执行，直至不再存在满足合并条件的页对或已满足预算为止。

**步骤四：得分删除（Score-Based Truncation）**

若合并之后文本页数量仍超出预算，以保留得分升序（分数最低者优先删除）截断，直至满足预算约束。

**锚点角色补位（Priority Guarantee）**：每组组内压缩完成后，检查该组锚点角色（`GROUP_PRIORITY_ROLE[g]`）是否出现在压缩结果中。若不存在，从未入选的候选中取保留得分最高的锚点候选，替换当前结果中得分最低的非视觉非锚点页；若无可替换页，则直接追加，允许超出一页预算。这一"允许超额"的设计选择体现了**演示质量优先于页数约束**的原则。

### 4.4.5 保留得分函数

保留得分（`keep_score`）是组内压缩阶段所有排序和选择决策的统一依据，其数学定义为：

$$\text{score} = \text{load} \times (1 + 0.3 \times C + 0.2 \times V)$$

其中：

$$C = \frac{\min(|\text{content\_points}|,\ 5)}{5} \in [0, 1] \quad \text{（内容密度）}$$

$$V = \min\!\bigl(0.5 \times N_{\text{img}} + 0.8 \times N_{\text{tbl}} + 0.3 \times N_{\text{eq}},\ 1.0\bigr) \in [0, 1] \quad \text{（视觉丰富度）}$$

$\text{load}$ 为幻灯片叙事角色对应的 `ROLE_BASE` 权重，$N_{\text{img}}$、$N_{\text{tbl}}$、$N_{\text{eq}}$ 分别为 `visual_refs` 中的图片、表格、公式数量。

**乘法加成结构的设计意图**：加成因子 $(1 + 0.3C + 0.2V)$ 的范围为 $[1.0, 1.5]$，最多将叙事分量基础分提升 50%。这保证了**角色决定上界**——即使 `hook_context` 拥有最丰富的视觉与内容，其最高分（$0.65 \times 1.5 = 0.975$）仍低于任何纯文字 `method_component`（$1.45 \times 1.0 = 1.45$）。叙事角色的不可替代性优先于内容或视觉的丰富程度。

视觉权重中表格系数（0.8）高于图片（0.5）高于公式（0.3），反映了数据型表格（直接呈现对比数字）在学术演示中比示意图（需要解读）更具直接证明力的经验规律。

典型场景下的保留得分分布如表 4-4 所示。

**表 4-4　典型场景保留得分示例**

| 场景 | load | C | V | score |
|---|---|---|---|---|
| `theoretical`，满内容 + 含表格 | 1.60 | 1.0 | 1.0 | **2.40** |
| `method_component`，满内容，无视觉 | 1.45 | 1.0 | 0 | **1.885** |
| `method_component`，内容较少，有图 | 1.45 | 0.4 | 0.5 | **1.885** |
| `hook_context`，满内容 + 含图 | 0.65 | 1.0 | 1.0 | **0.975** |
| `limitation_future`，内容稀少，无视觉 | 0.60 | 0 | 0 | **0.60** |

### 4.4.6 Pass 3：跨组叙事重排

**宏观组顺序**：前两个阶段输出的幻灯片按叙事组组序排列，形成演示叙事弧（Presentation Narrative Arc）。演示叙事弧与论文 IMRAD 顺序存在关键差异，如表 4-5 所示。

**表 4-5　论文 IMRAD 顺序与演示叙事弧的对比**

| 叙事阶段 | 论文 IMRAD 位置 | 演示叙事弧位置 | 调整原因 |
|---|---|---|---|
| 相关工作（`related`） | 引言之后，方法之前 | 问题之后、核心思想之前 | 先建立"别人做了什么"，再引出"我们的答案"，逻辑更紧凑 |
| 局限性（`gap_limitations`） | 分散于引言与讨论 | 紧接 `problem_definition` | 形成"问题 → 缺陷 → 方案"的完整动机链 |
| 实验设置（`experiment_setup`） | 实验节开头 | `evidence` 组首位 | 先建立实验可信度，再展示数字，避免听众对结论来源存疑 |

演示叙事弧借鉴了 Monroe 动机序列（Monroe's Motivated Sequence）：注意唤起（`opening`）→ 需求揭示（`problem` + `related`）→ 满足提出（`thesis` + `method`）→ 可视化论证（`evidence`）→ 行动号召（`closing`）。7 个叙事组是该序列在学术演示场景下的直接映射。

**组内微观排序**：同一叙事组内，幻灯片按三键优先级排序：

$$\text{排序键} = (r_i,\ \text{sec}_i,\ -\text{score})$$

其中 $r_i$ 为角色在组内叙事语法中的优先级索引（越小越靠前），$\text{sec}_i$ 为幻灯片所属章节在论文中的首次出现顺序（按原始章节推进顺序排列），$-\text{score}$ 用于在同角色同章节内优先选取质量更高的幻灯片。三键排序的实际效果如下（以 method 组为例）：

```
06 [method_overview   §4  ] HiAGM Model Overview     ← ri 最小，全局框架先呈现
07 [method_component  §4.1] Bayesian Graph Prior      ← sec_i 最小（§4.1 先出现）
08 [method_component  §4.2] BiTree-LSTM Encoder       ← sec_i 次之
09 [method_component  §4.2] Graph Convolutional Net   ← 同 section，score 降序
10 [method_component  §4.3] HiAGM-LA Variant          ← §4.3 最后
11 [theoretical       §4  ] Hierarchy Encoding Loss   ← ri 最大（细节放在 component 后）
```

此顺序遵循渐进式披露原则（Progressive Disclosure）：先呈现高层框架，再逐步深入技术细节，符合认知负载理论（Sweller，1988）的最佳实践。

### 4.5.1 端到端处理流程

图 4-1 展示了从输入论文 PDF 到输出演示文稿大纲的完整端到端流程：

```
    结构化章节树 parse_result
    │
    ├─────────────────────────────────────┐
    │（章节文本 + 图表引用列表）            │（图片文件列表）
    ▼ extract_elements                   ▼ upload_files
    元素列表（elements）                 图片 file_id 映射
    │                                    │
    └──────────────┬──────────────────────┘

                   │
                   ▼
输出：最终演示文稿大纲（N ≈ 16–21 张，叙事连贯）
```

### 4.5.2 决策透明度与可审计性

系统对每张原始候选幻灯片均记录三种压缩决策之一（`KEEP`/`MERGE → 目标页`/`DELETE`），并在终端输出完整的决策报告（`print_report`）。输出阶段清除所有运行时内部字段（以 `_` 开头的字段），仅保留业务字段，最终结果以标准 JSON 格式持久化至 `outputs/` 目录，供下游幻灯片渲染服务调用。

完整的审计链设计是算法可信度的关键保证：用户可以验证每个压缩决策的合理性，而非面对一个不透明的黑箱。对于研究者，可通过检查 `_merged_from` 字段追溯任意合并操作的源幻灯片；对于系统开发者，可通过参数调节（`ROLE_BASE` 权重、`GROUP_FLOOR` 地板、`target_n` 目标页数）直接干预压缩策略，而无需修改算法逻辑。

## 4.6 本章小结

本章提出并详细阐述了基于结构化中间表示的演示文稿生成方法。该方法以**幻灯片素材池**作为贯穿全流程的核心数据结构，通过以下两个关键技术设计实现了从学术论文到叙事连贯演示文稿的可控转换：

**一、14-Role 叙事角色分类体系作为跨模块语义合约。** 素材池构建阶段通过约束型提示词引导大语言模型为每张候选幻灯片标注预定义角色，叙事重排阶段通过叙事分量权重字典消费这些标签。两个模块之间形成明确的数据合约，使系统在保持模块独立的同时实现端到端的语义一致性。

**二、约束驱动的三阶段叙事重排算法保证生成质量下界。** Pass 2 的组内压缩通过视觉钉扎、语义合并和保留得分截断的有序执行，在满足视觉保全与叙事骨架双重硬约束的前提下最大化信息密度；Pass 3 的跨组重排将论文 IMRAD 线性结构重组为演示说服弧，从宏观结构层面实现了两种叙事范式的转换。

保留得分函数 $\text{score} = \text{load} \times (1 + 0.3C + 0.2V)$ 的乘法加成结构确保叙事角色的重要性决定保留优先级的上界，视觉丰富度与内容密度作为次级打分因子在同角色竞争中发挥差异化作用，体现了"叙事结构优先、内容质量次之"的设计原则。

与直接使用大语言模型进行端到端压缩的方案相比，本方法以规则系统处理结构约束，以大语言模型处理语义理解，两者分工明确，使得压缩决策完全可重现、可审计、可参数化调节，为学术场景下的自动演示文稿生成提供了一套可靠的工程基础。
